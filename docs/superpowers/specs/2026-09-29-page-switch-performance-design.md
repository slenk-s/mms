# 页面切换性能与全工程质量审查设计

**日期：** 2026-09-29
**状态：** 已确认，待实施计划
**范围：** MMS 桌面端全工程审查，以及物料、人员、资产页面在每类 5,000 条记录下的切换性能优化。

## 目标

先产出可执行、可追溯的全工程风险与质量审查报告；随后在不改变业务语义、不阻塞 Qt 主事件循环的前提下，降低库存、领用/人员、固定资产页面的切换延迟，并建立可重复的 5,000 条数据基准测试。

## 现状与问题陈述

- `client/main.py` 的 `MainWindow._on_page_changed()` 在调用 `QStackedWidget.setCurrentIndex()` 后同步调用 `_load_data_for_page()`。
- `_load_data_for_page()` 在主线程直接调用 `LocalDB.query()` / `LocalDB.get_all_users()`，然后调用页面的 `set_data()`、`set_materials()` 或 `set_records()`。
- 这条调用链会将 SQLite 查询、Python 数据整理和 Qt 表格重绘串行放在 GUI 线程。页面数据达到 5,000 条时，用户无法及时获得重绘和输入响应。
- `MainWindow._enter_main_ui()` 先直接加载库存页，再通过 `_on_page_changed("inventory")` 再次加载库存页，造成首次进入主界面的重复工作。
- `InventoryDetailView` 已具备搜索防抖和图片异步加载能力；当前缺少统一的页面级加载调度、结果过期保护和缓存失效策略。

## 非目标

- 本轮不替换数据库引擎、不改变 MySQL/SQLite 数据结构，也不修改同步协议。
- 本轮不将所有页面重写为 `QAbstractTableModel` 虚拟化架构。
- 本轮不改变现有权限矩阵、登录流程、业务字段或自动更新协议。
- 本轮不承诺特定绝对毫秒阈值；性能结论以同一机器、同一测试数据、相同测试步骤下的优化前后 P50/P95 对比为准。

## 阶段二：页面加载设计

### 方案选择

采用“异步数据加载 + 请求序号防过期 + 页面缓存精确失效”方案。

相比仅延迟加载，该方案将耗时查询移出 GUI 线程；相比全面 Model/View 虚拟化改造，它保持当前页面公共接口和业务表现，改动范围可控。

### 组件边界

| 组件 | 责任 |
| --- | --- |
| `MainWindow` | 维护当前页面、发起加载、接收加载完成结果、更新页面、处理缓存失效。 |
| 页面数据加载器 | 在工作线程中创建独立的 SQLite 只读连接，返回不可变的数据快照和请求元数据；不调用或持有 `LocalDB`，也不访问任何 Qt Widget。 |
| 页面视图 | 仅在 GUI 线程接收快照并调用既有渲染方法，不直接发起数据库读取。 |
| 页面缓存 | 保存已完成快照；缓存条目以页面标识和数据代次为键，避免在数据变化后使用旧快照。 |
| 基准测试 | 使用临时 SQLite 数据库构建三类各 5,000 条记录，测量首载、缓存命中和失效后重载。 |

### 加载生命周期

1. 用户点击导航按钮，`MainWindow` 立即调用 `setCurrentIndex()`；不在该同步路径执行数据库查询。
2. `MainWindow` 为该页面生成单调递增的请求号，并记录为该页面当前有效请求。
3. 缓存条目有效时，主线程直接交给页面渲染；缓存无效时，后台加载器使用独立的 SQLite 只读连接读取本地数据库。
4. 加载器仅返回页面标识、请求号、数据快照和可诊断的错误信息。
5. GUI 线程收到结果后，仅当请求号仍等于该页面当前有效请求、当前用户仍具有该页面权限时才渲染；其余结果被丢弃。
6. 用户快速切换页面时，较早完成的加载不能覆盖较晚请求的结果。
7. 查询失败时保留当前已显示内容，展示非阻塞错误提示；不切换到空白页面。

### 缓存失效规则

| 事件 | 失效页面 |
| --- | --- |
| 物料新增、编辑、删除或同步拉取物料变更 | `inventory`、`register` |
| 领用记录新增、归还、归档或同步拉取领用记录变更 | `register`、`inventory` |
| 固定资产新增、编辑、删除或同步拉取资产变更 | `asset` |
| 用户新增、编辑、删除或同步拉取用户变更 | `user_manage` |
| 系统配置修改或同步拉取配置变更 | `config` |
| 用户登出、切换车间、切换运行数据库 | 全部页面 |
| 用户手动刷新 | 当前页面；同步完成后按同步数据类型追加失效相关页面 |

缓存只保存本地数据库快照；不绕过同步引擎，也不缓存远程连接状态。`LocalDB` 保持现有“仅主线程调用”约束；后台读取通过独立连接完成。

### 首次登录修正

`MainWindow._enter_main_ui()` 只通过一次页面导航流程激活库存页，不再在调用 `_on_page_changed("inventory")` 前直接执行 `_load_data_for_page("inventory")`。

## 5,000 条基准测试

### 测试数据

每次测试创建独立的临时 SQLite 数据库，并写入：

- 5,000 条物料记录；
- 5,000 条人员/用户相关记录；
- 5,000 条固定资产记录；
- 页面渲染所需的最小关联记录和配置。

测试数据使用固定随机种子与确定性主键，保证本地和 CI 环境可重复。

### 测量场景

| 场景 | 测量起点 | 测量终点 |
| --- | --- | --- |
| 首次进入库存/人员/资产页 | 发出导航请求 | 该页收到并应用首个有效数据快照 |
| 缓存命中切换 | 发出导航请求 | 页面完成缓存快照应用 |
| 数据变更后的重载 | 触发失效并发出导航请求 | 页面完成新数据快照应用 |
| 快速连续切换 | 连续切换请求发出 | 最后一次请求对应页面完成应用，且没有过期结果覆盖 |

每种场景至少运行 10 次，记录 P50、P95、最小值、最大值和失败次数。报告中同时保留优化前基线与优化后数据。

### 正确性断言

- 所有 Qt Widget 更新都在主线程执行。\n- 工作线程不调用或持有 `LocalDB`；每个读取任务使用独立只读 SQLite 连接，并在任务结束时关闭。
- 缓存命中与失效重载的数据条数和关键主键集合一致。
- 过期请求结果不会调用任何页面渲染方法。
- 同步完成或数据变更后，受影响页面不会展示旧缓存。
- 现有登录、权限控制、手动刷新和同步提示行为保持可用。

## 风险控制与回滚

- 加载器不调用或共享 `LocalDB` 实例；它在工作线程内创建独立 SQLite 连接并设置 `PRAGMA query_only=ON`。数据库写入继续使用既有业务/同步路径。
- 异步读取连接启用 WAL 兼容的只读查询，并在每个任务结束时于所属线程关闭；写入仍由主线程 `LocalDB` 串行处理。
- 每类缓存失效建立测试，以防数据修改后页面长期显示旧数据；增加主线程写入与工作线程只读查询并发时不共享连接、不出现 `database is locked` 的回归测试。
- 若异步加载异常，临时回退到既有同步加载路径仅用于诊断，不作为默认发布行为。
- 将优化拆分为独立、可回滚的提交：审查报告、基准基础设施、加载器、页面集成、结果报告。

## 验收标准

1. 已生成覆盖约定模块的审查报告，所有发现均有可定位证据与优先级。
2. 三类页面均能在各 5,000 条数据下完成自动化基准场景。
3. 优化后没有新增测试失败，快速连续切换不会渲染过期结果。
4. 优化后页面切换 P50/P95 相较基线可量化，并在基准报告中记录。
5. `git diff --check`、受影响测试和项目 CI 等价检查均通过。
