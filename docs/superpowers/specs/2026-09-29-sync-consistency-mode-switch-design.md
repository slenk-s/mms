# 数据一致性、断网重试与运行模式切换设计

**日期：** 2026-09-29
**状态：** 已确认，待实施计划
**范围：** SQLite 离线队列、MySQL 同步、网络故障重试及 `online` / `semi_offline` / `offline` 模式切换稳定性。

## 目标

在网络抖动、MySQL 超时、客户端重启和运行模式切换期间，确保本地业务变更可追踪、可重试、不会因重复提交重复写入，并使界面配置、网络监测和同步引擎保持同一稳定状态。

## 当前边界

- SQLite `LocalDB` 继续仅由主线程业务路径读写；页面后台读取器不共享 `LocalDB`。
- MySQL 网络 I/O 继续在同步 worker 中执行；本地队列状态变更通过主线程完成。
- 不引入外部消息队列或服务端中间件。
- 不修改物料、领用、资产、用户和员工的业务字段含义。

## 同步状态机

### 队列状态

每条 `sync_queue` 操作使用以下状态：

| 状态 | 含义 | 可转移目标 |
| --- | --- | --- |
| `pending` | 已持久化，等待处理 | `in_progress` |
| `in_progress` | 已被当前同步批次领取 | `succeeded`、`retryable`、`failed` |
| `retryable` | 网络/超时等暂时故障，等待退避后重试 | `in_progress`、`failed` |
| `failed` | 不可重试的数据、权限或冲突错误，等待人工处理 | `pending` |
| `succeeded` | 服务端确认且本地已确认完成 | 终态，可清理 |

每条记录新增或持久化以下元数据：操作 ID、尝试次数、最后错误、下次可重试时间、领取批次 ID、状态更新时间。

### 幂等与批次确认

1. 本地写入和队列入列在同一 SQLite 事务中完成。
2. 同步 worker 按批次领取可执行的 `pending` / 到期 `retryable` 记录，先标记为 `in_progress`。
3. 每条 MySQL 写入携带稳定操作 ID；重复提交必须被识别为同一逻辑操作，而非再次执行业务写入。
4. MySQL 成功提交后，主线程才将对应本地记录标记为 `succeeded`。
5. 若 MySQL 已提交但响应在网络中丢失，重试同一操作 ID；服务端返回已处理结果时，本地安全标记成功。
6. 进程启动或模式切换恢复时，遗留的 `in_progress` 记录回收为 `retryable`，避免永久卡住。

### 错误分类和退避

| 类型 | 例子 | 行为 |
| --- | --- | --- |
| 可重试 | 网络不可达、连接超时、MySQL 瞬时断链 | 标记 `retryable`，指数退避后重试 |
| 已处理但响应未知 | 服务端提交后客户端超时 | 使用同一操作 ID 查询/重放，禁止生成新操作 |
| 不可重试 | 字段校验失败、权限错误、不可自动合并冲突 | 标记 `failed`，保留错误并提示人工处理 |

退避按有限指数增长，并受 `SYNC_RETRY_MAX` 约束；超过上限后转入 `failed`，不允许无限循环。

## 运行模式切换状态机

### 稳定状态

- `online`：网络监测启用，自动同步启用，队列可自动推送和拉取。
- `semi_offline`：网络监测启用，自动定时同步暂停，允许用户主动同步。
- `offline`：网络监测和同步 worker 均停止，业务仅写入 SQLite 与队列。

### 受控切换流程

1. 设置模式控制状态为 `switching`，UI 禁止重复切换和新的自动同步批次。
2. 停止同步定时器，阻止新的队列领取。
3. 等待当前 MySQL worker 在限定时间内完成；无法完成的批次安全释放为 `retryable`。
4. 持久化目标模式配置与当前队列状态。
5. 依据目标模式启动或停止网络监测、同步 worker 和自动定时器。
6. 对目标组件做健康检查；全部通过后更新 UI 为新稳定模式。
7. 任一阶段失败时，停止半启动组件，恢复上一个稳定模式及其定时器/监测状态，并显示可诊断错误。

切换完成后，配置值、`MainWindow._app_mode`、`SyncEngine` 状态、`NetworkMonitor` 状态和状态栏模式文本必须一致。

## 验证矩阵

| 场景 | 期望结果 |
| --- | --- |
| 离线新增后恢复在线 | 本地记录与单一队列操作最终仅同步一次 |
| MySQL 写入成功但响应超时 | 重试使用同一操作 ID，不重复扣库存或新增记录 |
| 可重试错误超过上限 | 记录转为 `failed`，保留最后错误，不再自动循环 |
| 应用重启时存在 `in_progress` | 队列恢复为可重试状态，不遗失操作 |
| online 切 offline 且同步在途 | 在途操作完成或回到 `retryable`，后台组件完全停止 |
| offline 切 online | 队列保留，网络恢复后按退避/批次规则处理 |
| semi_offline 切 online | 自动同步恢复且不会创建重复 worker/timer |
| 模式切换健康检查失败 | 恢复前一稳定模式，UI 和后台状态一致 |

## 验收标准

1. 每个同步操作都有稳定操作 ID、状态和可诊断错误信息。
2. 网络超时和重试不会产生重复业务写入。
3. 重启和运行模式切换不会遗留永久 `in_progress` 队列项。
4. 三种运行模式之间的双向切换可验证，失败时能回滚到上一稳定状态。
5. SQLite 事务、队列状态转换和 MySQL 批次确认均有自动化回归测试。
6. 页面后台读取器不受影响，仍不跨线程共享 `LocalDB`。
