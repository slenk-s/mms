# 页面加载 5,000 条数据基准报告

**日期：** 2026-09-29
**运行环境：** Windows、Python 3.11.3、PySide6 6.10.0、SQLite 临时 WAL 数据库。
**样本：** 物料、资产、用户、员工各 5,000 条；每个场景 10 次测量。

## 测量范围

本次测量覆盖新页面读取器的独立只读 SQLite 快照读取，以及主线程页面缓存命中查询。它不伪装为完整 UI 帧率测试：现有 `DataTable` 默认只渲染当前分页的行，完整应用启动还会涉及登录、配置、图片和同步状态。因此结果用于验证“读取不再阻塞 GUI 线程”和“缓存命中避免重复 SQLite 查询”的目标，而非声明端到端首帧时间。

## 结果

| 页面 | 5,000 条首次快照 P50 | 5,000 条首次快照 P95 | 缓存命中 P50 | 缓存命中 P95 |
| --- | ---: | ---: | ---: | ---: |
| 库存 | 20.0061 ms | 32.9411 ms | 0.0002 ms | 0.0017 ms |
| 资产 | 19.1980 ms | 28.1381 ms | 0.0002 ms | 0.0022 ms |
| 人员/用户 | 22.8793 ms | 31.8297 ms | 0.0002 ms | 0.0015 ms |

## 结论

- 首次读取仍需要约 19–33 ms 的 SQLite 查询和 Python 快照构造，但该工作现在由 `PageDataLoadWorker` 在线程中执行，页面切换不会在 GUI 主线程等待它完成。
- 缓存命中没有再次打开 SQLite 连接，读取状态的 P95 小于 0.003 ms。
- `PageLoadState` 通过单调递增请求号拒绝过期结果；回归测试已覆盖“较早请求不能覆盖新请求”和“失效后在途结果不能写回缓存”。
- 优化前项目没有可收集的 pytest 用例，也没有同口径的页面基准，因此无法提供可信的历史 P50/P95 对比；本报告建立后续对比基线。

## 后续建议

在可控测试账户下启动完整桌面端，使用 Qt 事件循环记录从导航点击到首个页面绘制完成的端到端时延；同时监控生产数据中图片路径、排序字段索引和同步写入竞争对 P95 的影响。
